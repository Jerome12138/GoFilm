### 关键决策

1. **preset-icons 暂时禁用**：unocss 0.62.4 + @iconify-json/carbon 1.2.5 在 build 阶段会输出非法 CSS（`Missed semicolon` 错误）。改用 BaseIcon 组件的 inline SVG 集合托底。后续 story 可考虑升级 unocss 至 ^0.65 或换用 unplugin-icons。

## STORY-011 + STORY-012（Search / Classify / ClassifySearch）— 完成

完成时间：2026-05-08

### 交付清单

#### 新增 composable
- `src/composables/useQuerySync.ts` — 路由 query <-> 数据 ref 双向绑定。
  - `useQuerySync<T>(initial, { path?, onChange? })` → `{ params, push, replace }`
  - 单向同步：watch route.query → params；ref 不会反向写 URL，必须主动 `push()`
  - `push` 会立即更新本地 ref 并加 `suppressNext` 跳过下一次 watch 回调（避免 onChange 循环）
  - 跳过 undefined / null / '' 字段（不写入 URL，不带回业务）
  - 类型安全：根据 initial 中字段的类型自动 coerce string → number/boolean

#### 改造 view
- `src/views/public/SearchView.vue`（重写）— 顶部圆角搜索框 + 列表结果
  - 移动端：左海报右信息卡片（`gf-search__row-mobile`）
  - 桌面：FilmGrid 渲染（每行 2 列），item slot 自定义详情卡（`gf-search__row-desktop`）
  - 路由 query：`search`, `current`
  - API：`filmApi.searchFilm({ keyword, current }, { signal })`
  - 切页通过 `push({ ..., current: p })` 更新 query
  - 空结果用 BaseEmpty + 返回首页 CTA
  - 未输入关键字时也显示 BaseEmpty 引导

- `src/views/public/ClassifyView.vue`（重写）— 分类首页
  - 顶部 title：当前分类（gradient text）+ "XXX 库" 链接
  - 三个 FilmRow：最新上映（Sort=release_stamp）/ 排行榜（Sort=hits）/ 最近更新（Sort=update_stamp）
  - 每行右上"更多 >"路由到 `/filmClassifySearch?Pid=&Sort=...`
  - 路由 query：`Pid`
  - API：`filmApi.getClassify(Pid)` 返回 `{ title, content: { news, top, recent } }`
  - 加载阶段三段骨架（每段 1 行 6 张占位卡）

- `src/views/public/ClassifySearchView.vue`（重写）— 分类筛选
  - 顶部 title：当前页"XXX 库"高亮
  - 筛选栏：FilmFilterBar，groups 来自后端 `search.{ sortList, titles, tags }`
  - 当前 active 项依据 `params[key]`，点击 chip → `push({ [key]: value, current: 1 })`
  - 影片网格 FilmGrid + BasePagination
  - 路由 query：`Pid`, `Category`, `Plot`, `Area`, `Language`, `Year`, `Sort`, `current`（**严格大小写！**）
  - API：`filmApi.searchClassify(params, { signal })` 返回 `{ title, list, page, search, params }`

#### 类型扩展
- `src/types/film.ts` — 关键变更（**与原占位类型不兼容**）
  - `ClassifyData` 从原 `{ pid, category, newest, ranking, recent }` 改为 **后端真实字段** `{ title, content: { news, top, recent } }`
  - 新增 `BackendPage`（`pageSize / current / pageCount / total`）
  - 新增 `ClassifySearchResp`（包含 search.sortList/titles/tags 与 params）
  - 新增 `SearchFilmResp`（list + page）
  - `ClassifySearchParams.Pid` 放宽为 `number | string`，`Year` 放宽为 `string | number`
  - 新增 `ClassifyTitle`、`ClassifyTagItem`

#### API 调整
- `src/api/film.ts`
  - `getClassify(Pid: number | string): Promise<ClassifyData>` — 返回类型改为新结构
  - `searchClassify(params, { signal? }): Promise<ClassifySearchResp>` — 返回完整对象（包含 search/params/page）
  - `searchFilm(params, { signal? }): Promise<SearchFilmResp>` — 返回 `{ list, page: BackendPage }`
  - 不再依赖 `PaginationResp<FilmListItem>`（旧泛型与后端字段不一致：后端字段是 `pageSize / pageCount`，不是 `size / pages`）

### 关键决策与坑点

1. **类型与后端实际响应对齐**：原占位类型 `ClassifyData.{ newest, ranking, recent }` 与后端 `content.{ news, top, recent }` 不符。架构文档第 8 节也未列出 search 子对象。**调整后端返回字段名风险高**，因此前端类型适配后端约定。
2. **query 大小写**：`Pid / Category / Plot / Area / Language / Year / Sort` 首字母大写，`current` 小写。useQuerySync 内部按 initial 字段名做读写映射，从入口写正确即可。
3. **useQuerySync 防循环**：push 内部立即更新 ref + `suppressNext` 标记，下一次 route.query watch 触发时 ref 已等于新值，浅比较跳过 onChange，从根上避免重复请求。
4. **AbortController 复位**：列表/筛选请求都走 `useAbortable.refresh()`，路由切换或快速连续点击 chip 时上一次请求会被 abort（CanceledError 在 catch 中静默处理）。
5. **FilmFilterBar 已有组件直接复用**：组件内部用 `String(opt.value) === String(group.current)` 做高亮判断，把 params.value[key] 转 string 即可。
6. **空结果 / 未输入两种状态都用 BaseEmpty**：避免空白页给用户错觉。
7. **滚动重置**：分页切换后 `window.scrollTo({ top: 0, behavior: 'smooth' })`。

### 后端字段疑问 / 待确认（不阻塞开发）

1. `filmClassify` 返回的 `title` 字段，旧 client 用 `d.title.id`、`d.title.name`，但架构文档未列出明确 DTO（NavCategory 字段名是 `id/pid/name/show`，应该一致）。已用 `ClassifyTitle` 兼容，**待联调时校对**。
2. `filmClassifySearch.search.tags[key]` 列表项字段是 `Name / Value`（首字母大写），与旧站一致，前端按此渲染；如果后端将来改为 `name/value` 需要同步前端。
3. `searchFilm` 返回 page 缺少 `pageSize` 时按 10 兜底（旧后端硬编码为 10）。
4. `filmClassifySearch` 返回 page.pageSize 为 49（后端硬编码），如果未来后端调整需要前端配合放宽 BasePagination 的最大显示数。
5. 旧站 `搜索` 时仅返回 `list / page`，不返回 keyword；前端用 query.search 显示"关键字回显"。

### 关键设计决策

1. **Header 滚动监听 vs IntersectionObserver**：window scroll 事件实现简单且能精确到 12px 阈值；IntersectionObserver + sentinel 在路由切换时可能因 sticky 计算抖动。
2. **历史浮层 hover 延时关闭**：使用 200ms `setTimeout` 防止鼠标移动到浮层边缘时闪退，比 CSS `transition-delay` 更可控。
3. **Hero 与 Header 的层叠**：Header `--top` 状态保留淡黑色渐变背景（不是完全透明），因为 hero 顶部经常是亮色海报，纯白文字会被淹没。
4. **FilmDetail hero 模糊背景**：`background-image: url()` + `filter: blur(40px) brightness(0.4)` + `inset: -40px` 防止 blur 边缘出现透明断层；`isolation: isolate` 隔离层叠上下文不污染外部。
5. **HomeView lg+ 旁栏**：用 `:deep(.gf-film-row > header.container-page)` 覆盖 FilmRow 内部 container，让 row 与 sidebar 在双列布局下平铺。这是少数必须穿透的场景。
6. **剧情字段清洗**：保留旧站正则形式 `/(&.*?;)|( )|(　　)|(\n)|(<[^>]+>)/g`，把第一段改为非贪婪 `&.*?;`，避免吃掉合法分号后的内容。
7. **导演/主演切片**：`split(/[,，、\/\s]+/)` 兼容中英文逗号、顿号、斜杠、空格四种分隔，导演取前 3、主演取前 5。
8. **HistoryRecord 兼容旧字段**：旧站 cookie 历史结构是 `{ id, name, link, episode, timeStamp, picture? }`，本期 Header 浮层优先 `router.push(item.link)`，缺失 link 时降级到 `{ path:/play, query:{ id, source, episode } }`。

## STORY-010（PlayView 播放页）— 完成

完成时间：2026-05-08

### 交付清单

- `src/composables/usePlayer.ts` — video.js 播放器封装（命令式 API + 响应式 src 切换）
- `src/composables/useFilmHistory.ts` — 播放页观看历史粘合（自动 onBeforeUnmount + beforeunload 写入）+ buildPlayLink 工具
- `src/stores/history.ts` — **重写**为旧站 `{ [filmId]: ... }` 对象映射结构（兼容旧站 cookie），双写 cookie + localStorage，向下兼容数组结构
- `src/types/film.ts::PlayInfo` — **更正**为后端实际响应结构：`{ detail, current, currentPlayFrom, currentEpisode, relate }`（旧定义只有 `src/episode/link/prev/next` 全错）
- `src/views/public/PlayView.vue` — 完整重写
- `src/components/base/BaseIcon.vue` — 扩 7 个图标（pause / play-circle / skip-next / skip-prev / volume-up / volume-down / autoplay）
- `src/components/layout/PublicHeader.vue` — 浮层跳转改用 `router.push(item.link)`，保留续播 currentTime
- `src/assets/play.png` — 从旧站复制的 poster 占位图

### 关键设计

#### 1. usePlayer composable
- video.js 实例存 `shallowRef`，避免 Vue 深 reactive 把内部上千个属性都包进去
- 切换 src 通过 `player.src({src,type})`，**不重建 player**，preserve volume / playbackRate / fullscreen 状态
- 暴露：`init(el) / dispose() / play / pause / seek / seekBy / setVolume / on(evt,fn) / off(evt,fn)`
- 支持 ready 之前调用 on() —— 内部 pendingListeners 队列，ready 时统一 flush
- onScopeDispose 自动 dispose（双保险，PlayView 内 onBeforeRouteLeave 也手动 dispose）
- 不在 composable 内触发 router / toast，由调用方决定（架构守则要求）

#### 2. useFilmHistory composable
- 目标：让 PlayView 在「卸载 / beforeunload / 切换 episode」三个时机都把当前进度写一次
- 通过 `collect()` 回调拉取最新快照，store.record 入库
- store 同时持久化 cookie + localStorage（cookie 4KB 兜底，localStorage 主存）
- buildPlayLink 工具统一拼 `/play?id=&source=&episode=&currentTime=`

#### 3. cookie 结构兼容
- 旧站结构：`{ [id]: { name, link, episode, timeStamp } }`
- 新站新增字段：`source / episodeIndex / currentTime / picture`（旧站读取时忽略多余字段，仍可工作）
- 新站读取时兼容数组结构（早期 STORY-006 阶段曾用 array），自动转 map
- 序列化前 `toRaw()` 避免 reactive proxy 报错（旧站踩过的坑）
- 排序写入：按 timeStamp 倒序，截断到 100 条

#### 4. 集数切换流程
1. 用户点 EpisodeTabs 触发 `selectEpisode({sourceId, episodeIndex})`
2. flushHistory() 写当前进度
3. 更新 currentSourceId / currentEpisodeIndex
4. `currentSrc.value = ep.link` → usePlayer 监听到 ref 变化，调 player.src(...)
5. router.replace 同步 query（不重新加载）
6. nextTick 后 playerPlay()
- watch route.query 时只在 path 仍为 /play 时响应，且 selectEpisode 内部已用 router.replace 同步，watch 是幂等的（影片切换时才重新 loadPlayInfo）

#### 5. 键盘 / D-pad 快捷键
- 全局 window.keydown 监听，先用 `normalizeDpadKey(e)` 把 D-pad keyCode 转标准 key
- 输入框 / contenteditable 聚焦时跳过
- Space/Enter：暂停/播放（按钮聚焦时不抢）
- ArrowLeft/Right：±10s
- ArrowUp/Down：音量 ±5%
- Escape：返回详情

#### 6. 错误处理
- API 失败：`loadError` 设值 → BaseEmpty 渲染 + 返回首页按钮
- video error 事件：on-page banner + 自动尝试下一个播放源（取模轮询）

#### 7. 大屏 / TV 适配
- 播放器外层 `aspect-ratio: 16/9`，桌面 ≥ 1280 居中限宽 1280

### 关键设计决策

1. **空间导航算法**：DOM 几何位置 + 主轴优先 + 副轴次要分（×0.5），对完全错位（行/列偏移大于元素自身尺寸）加 1.5 倍惩罚。这种简单评分对线性 grid 与 row 表现良好，复杂场景由 focusin 事件辅助滚动。
2. **D-pad bridge 在所有模式下都安装**：无 keyCode 19/20/21/22/23 时无副作用，避免 mode 切换时漏装；空间导航由 `isTV` watcher 控制启用。
3. **焦点记忆**：用 fullPath 当 key，元素稳定 ID 优先级 `#id > data-* / aria-label > tag+attrs > 索引`。tv 用户离开页面再回来焦点会落回上次位置（购物车场景常用模式）。
4. **HeroCarousel 自动 focus**：onMounted 后 setTimeout 250ms 扫描 `button[data-focusable]`，仅当 activeElement 仍是 body 时才接管，避免覆盖空间导航 restoreFocus / 用户交互。
5. **TV history Dialog 替代 hover 浮层**：hover 在遥控器场景不可用，dialog 模式更直观；BaseDialog 已支持 ESC 关闭 + 自动 focus dialog 内部，与空间导航协同。
6. **focus + focus-visible 双覆盖**：Chromium 在 D-pad 派发的 keydown 后未必触发 :focus-visible（取决于 keyboard event trust state），全局样式同时匹配 :focus 与 :focus-visible 防丢样式。
7. **TV 模式样式仍走 unscoped 块**：Vue scoped 不支持 `:global()`，按 06-frontend.md 的约定。

### 反模式对照（自查）

- ✅ 没有破坏现有 mobile/desktop 行为，所有改动以 [data-mode='tv'] 限定
- ✅ data-focusable 只加在交互元素（button / a / input），未滥用
- ✅ keydown listener 装在 capture 阶段，preventDefault 由 spatial nav / dpad bridge 决定
